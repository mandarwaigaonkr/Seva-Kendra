# Deploying Seva Kendra (free)

- **Website:** Render static site. Free, served from a CDN, never sleeps.
- **API:** Render free web service in Singapore. It sleeps after 15 idle minutes and takes up to about a minute to wake. While it wakes, the app shows "Starting the server…" and carries on by itself.
- **Database:** MongoDB Atlas free M0 cluster.

Both services are defined in `render.yaml`. Set them up once and every push to `main` redeploys.

## 1. Database (MongoDB Atlas)

1. Create a free account at mongodb.com/atlas and create a cluster: **M0 (free)**, provider **AWS**. For the region:
   - **Singapore (ap-southeast-1)** is next to the API, so pages are fastest.
   - **Mumbai (ap-south-1)** keeps the data in India, with about 60 ms added to each request. Choose this if the NGO needs data kept in India.
2. **Database Access → Add user.** Use password authentication with a generated password, role *Read and write to any database*.
3. **Network Access → Add IP address → `0.0.0.0/0`.** Render's free plan has no fixed outgoing IP, so the strong password is what protects the database.
4. **Connect → Drivers** gives you the connection string. Put the database name before the `?`:
   `mongodb+srv://USER:PASSWORD@cluster0.xxxxx.mongodb.net/sevakendra?retryWrites=true&w=majority`

## 2. Render

1. Sign up at render.com with GitHub. Then go to **New → Blueprint**, pick this repository and apply.
2. When asked for values:
   - **`MONGO_URL`**: the Atlas string from step 1.
   - **`FRONTEND_URL`**: the website's address, `https://seva-kendra.onrender.com`. If Render added a suffix to the name, use the address it shows for the **seva-kendra** service.
   - **`VITE_API_URL`**: the API's address plus `/api/v1`, for example `https://seva-kendra-api.onrender.com/api/v1`.

   `JWT_SECRET` is generated by Render. Never commit it.
3. If an address differs from what you typed, fix it under the service's **Environment** tab. Redeploy the website after changing `VITE_API_URL`, because it's built into the page.

## 3. First admin

1. In Render, open **seva-kendra-api → Shell** (or run this locally with `MONGO_URL` set to Atlas):
   `node scripts/createAdmin.js`
2. Sign in as `admin@sevakendra.com` / `Admin@123`, then **change that password straight away** in Users & access.

## 4. Optional extras (GitHub → Settings → Secrets and variables → Actions)

- **Fewer wake-ups:** add the *variable* `API_HEALTH_URL` = `https://seva-kendra-api.onrender.com/health`. The API is then pinged every 10 minutes, 09:00–19:00 India time, Monday to Saturday (`.github/workflows/keep-api-warm.yml`). That is about 300 of Render's 750 free hours a month.
- **Nightly backups** (the free Atlas tier keeps none):
  - Make the repository **private**. The workflow refuses to run on a public repo.
  - Add the *secrets* `MONGO_URL` (a read-only Atlas user is enough) and `BACKUP_PASSPHRASE` (a long random phrase; keep a copy somewhere safe).
  - Backups are encrypted and kept for 14 days under **Actions → Back up database**. To restore one:

    ```sh
    openssl enc -d -aes-256-cbc -pbkdf2 -iter 200000 -in sevakendra-YYYY-MM-DD.archive.gz.enc -out db.archive.gz -pass pass:'YOUR PASSPHRASE'
    mongorestore --uri="$MONGO_URL" --archive=db.archive.gz --gzip --drop
    ```

## Domain

The `*.onrender.com` addresses already have HTTPS. For your own domain later, add it under the website's **Settings → Custom Domains**, then add it to the API's `FRONTEND_URL` (comma-separated).

## Behaviour on the free plan

- The first visit after a quiet spell shows "Starting the server…" for up to about a minute. Anything requested meanwhile, including sign-in, goes through by itself once the server is ready.
- If the server doesn't answer within two minutes, the app says it can't reach the server and offers **Try again**.
- Lists you have just viewed are kept in memory for 30 seconds, so moving between pages is instant. Saving anything clears them.
